# UIタイムアタック 注文端末アプリ

オープンキャンパス展示用の注文端末アプリです．iPad横向きでの利用を想定しています．

## 使い方

1. `index.html` をブラウザで開きます．
2. 右上の「設定」から，端末IDと送信先URLを設定します．
   - 端末ID例：`iPad01`，`iPad02`，`iPad03`
   - 送信先URL：Google Apps Script の doPost 受付URL
3. 体験者はニックネームを入力します．
4. 端末側で AB／BA の順番を自動決定します．初回はランダム，以降は交互です．
5. 体験者は注文アプリA／Bを2回体験します．
6. 2回分の結果をまとめて送信します．
7. タイムや正誤は端末側では表示せず，大型モニター側で確認します．

## 送信先URLについて

`config.js` の `SEND_ENDPOINT_URL` にURLを書いておくこともできます．端末ごとに変更したい場合は，画面右上の「設定」から保存してください．

## 注文カードの変更

`app.js` の `ORDER_CARDS` を編集してください．

```js
const ORDER_CARDS = [
  { card_id: 'C01', label: '①', menu: '唐揚げ定食', amount: '大盛', add_on: 'ウーロン茶', payment: '現金' },
  ...
];
```

紙の注文カードと同じ内容にしてください．


## メニュー表示

注文アプリA／Bともに24品構成です．各カテゴリ8品を，2列×4行で表示します．

- 注文アプリA：`定食`，`カレー・丼もの`，`麺類`
- 注文アプリB：`おすすめ`，`人気`，`定番`

品目数は同じにし，カテゴリ分類と写真の有無でUIの違いを体験できるようにしています．

## アプリAの写真差し替え

`images/tonkatsu.jpg` など，料理名に対応するファイル名で差し替えてください．
現在はVGAサイズのグレー画像を仮で入れています．

## 送信データの概要

送信時は，1人分のA/B結果をまとめたJSONを送ります．

```json
{
  "pair_id": "P2026...",
  "participant_id": "P2026...",
  "nickname": "さな",
  "display_name": "さな",
  "device_id": "iPad01",
  "planned_order": "AB",
  "event_id": "OC2026_01",
  "source": "opencampus",
  "results": [
    {
      "trial_no": 1,
      "app_id": "A",
      "card_id": "C01",
      "time_ms": 19700,
      "selected_menu": "唐揚げ定食",
      "selected_amount": "大盛",
      "selected_addon": "ウーロン茶",
      "selected_payment": "現金"
    }
  ]
}
```

## 注意

- カウントダウンは計測時間に含めていません．
- 2回目では1回目と同じ注文カードは選択できません．
- 送信に失敗した場合は未送信データとして端末に保存し，再送信できます．


## 音声ファイルの差し替え

`audio/bgm.mp3` と `audio/click.mp3` を配置すると，それぞれ競技用BGMとクリック音として再生されます．  
音源ファイルが見つからない場合は，ブラウザ内で生成する簡易BGM／クリック音に自動で切り替わります．

音声の有効／無効は，右上の「設定」画面の「音を出す」から切り替えられます．  
`config.js` では以下を変更できます．

```js
ENABLE_AUDIO: true,
BGM_SOURCE: "audio/bgm.mp3",
CLICK_SOURCE: "audio/click.mp3"
```

著作権のある音源は使用せず，フリー素材や自作音源を利用してください．
